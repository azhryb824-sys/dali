## ضوابط SEO المعتمدة في التنفيذ

1. لا تُنشأ صفحات مدن مكررة لمجرد استهداف الكلمات؛ تنشر صفحة مدينة فقط بعد وجود تغطية معتمدة ومحتوى محلي مفيد. يتسق ذلك مع سياسة Google التي تعد صفحات المدن المتشابهة المحوِّلة إلى وجهة واحدة doorway abuse.
2. لكل صفحة حرجة عنوان ووصف فريدان، مع اعتماد النص المرئي أساساً للملخص وليس حشواً من الكلمات المفتاحية.
3. تستخدم صفحة المقاولات `Service` مع `areaServed=Saudi Arabia`، ويصف كيان المنشأة في الرئيسية نطاق المملكة.
4. تم الحفاظ على العربية الفصحى، اتجاه RTL، وبنية عناوين واضحة وروابط داخلية ونموذج ذي نتيجة قابلة للمتابعة.
5. الهدف الفني اللاحق عند القياس الحقيقي: LCP أقل من 2.5 ثانية، INP أقل من 200ms، وCLS أقل من 0.1 وفق إرشادات Core Web Vitals.

المراجع الأساسية: Google Search Central (SEO Starter Guide، Spam Policies، Snippets، Core Web Vitals) وSchema.org (`Service`, `HomeAndConstructionBusiness`, `areaServed`).

## ما لا يُفعّل تلقائياً دون بيانات أو قرار مالك النظام

- نشر صفحة مستقلة لكل مدينة: يتطلب اعتماد القدرة التشغيلية ومادة محلية أصلية؛ إنشاء عشرات الصفحات المتشابهة يعرض الموقع لمخالفة doorway pages.
- تطبيق migrations على قاعدة الإنتاج: ملفات الترحيل جاهزة ومتحققة، لكن التطبيق الحي يحتاج نافذة إصدار ونسخة احتياطية واعتماد نشر.
- النشر إلى الإنتاج أو دفع الفرع: يحتاج اعتماداً صريحاً لعملية النشر/الدفع.
- بيانات التراخيص، المشاريع المنجزة، التقييمات، العناوين والفروع: لا تُخترع لأجل SEO، وتضاف بعد تقديم مستند موثق.

## بوابات القبول قبل الإنتاج

- `npm run typecheck`
- `npm run lint`
- `npm run build`
- `node --test tests/*.test.mjs`
- تطبيق migration في بيئة مرحلية ثم اختبار إنشاء طلب عام، ظهور التنبيه، تحويل فرصة فائزة إلى مشروع، وإنشاء مركز التكلفة.
- فحص Rich Results/Schema وSearch Console وقياس Core Web Vitals بعد توفر رابط النشر.
