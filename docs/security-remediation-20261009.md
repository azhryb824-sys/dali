# معالجة أمنية مع الحفاظ على الدخول

- تحديد مصدر حد المحاولات من آخر عنوان في X-Forwarded-For، بدلاً من تفضيل CF-Connecting-IP وأول عنوان يمكن للمتصل تزويرهما. اختبار بقاعدة PostgreSQL معزولة يثبت أن تغيير الترويسات المزورة لا يمنح حصة جديدة، وأن عنوان مستخدم آخر يحصل على حصته المستقلة.
- إضافة script-src-attr 'none' لمنع معالجات JavaScript داخل سمات HTML. أحداث React وسكربتات Next.js المضمنة تبقى مسموحة وفق السياسة الحالية. لم توجد سمات onclick/onerror/onload نصية في كود الواجهة المفحوص.
- لا تغيير لسياسة الأدوار أو مسارات الدخول أو رموز الأجهزة أو الكوكيز أو بيانات الحسابات. لا أحداث تشغيلية جديدة تستلزم إشعارات.

التحقق: 31 اختباراً ناجحاً للأمان والهوية والتطبيقات والدخول المعتمد، إضافة إلى TypeScript. اختبارات توافق الدخول هنا محلية؛ لم تستخدم جلسة حساب إنتاج فعلي.

قبل النشر يجب التأكد أن Nginx يستبدل X-Forwarded-For بعنوان المتصل أو يضيفه باستخدام $proxy_add_x_forwarded_for، وأن منفذ Node غير متاح خارج الوكيل. إذا كان هناك CDN أمام Nginx، يلزم ضبط real_ip للمصادر الموثوقة كي لا يتشارك زوار CDN حصة واحدة. لم يتم فحص إعداد الخادم الفعلي أو تغييره في هذه الجولة، فلا تعد هذه الشروط مؤكدة.

لم يثبت الفحص الشبكي ثغرة XSS أو تجاوز أدوار؛ هذه تقوية محددة ومنع لتزوير مصدر حد المحاولات تحت شروط الوكيل المذكورة، وليست ادعاء بإغلاق جميع الثغرات. تظل الحالات التي منعها وكيل الفحص غير محسومة. إخفاء إصدار Nginx يحتاج إعداد الخادم، ولم ينفذ. لم تنشر التغييرات.
