# بنية الظهور العضوي والأمان

آخر مراجعة: 2026-08-14

## الهدف

تبني المنظومة الظهور في البحث على صفحات مفيدة ومحددة النية، لا على تكرار الكلمات المفتاحية. لا يمكن تقنيًا ضمان المركز الأول؛ لأن الترتيب يتأثر أيضًا بالمنافسة، والمسافة، والشهرة المحلية، والسمعة، وجودة الروابط والإشارات الخارجية. الهدف القابل للقياس هو جعل الموقع قابلًا للزحف والفهم، وتقديم أفضل إجابة فعلية عن خدمات دالي في مكة، ثم متابعة الأداء والتحسين بالبيانات.

## مصدر الحقيقة

- `lib/site.ts`: الاسم والعنوان والنطاق والصور الأساسية. لا تُكرر بيانات المنشأة يدويًا في الصفحات الجديدة.
- `lib/website-content.ts`: مخطط محتوى الموقع، القيم الابتدائية، التنقية، حالات المسودة/النشر، وترابط الخدمات والقطاعات والمواقع والمشروعات والاعتمادات والمقالات والوظائف والشركاء.
- `portal_settings.website-content-v1`: النسخة التي تنشرها الإدارة من وحدة «إدارة الموقع»، مع رقم إصدار وتاريخ ومحرر آخر تعديل.
- `lib/service-catalog.ts` و`lib/insights.ts`: مصدر تهيئة المحتوى القديم فقط عندما لا توجد نسخة إدارية محفوظة.
- `app/sitemap.ts`: يولد خريطة الموقع من المحتوى المنشور والظاهر فقط، ويستخدم تاريخ التعديل الحقيقي بدل وقت الطلب.
- `app/components/StructuredData.tsx`: يسلسل JSON-LD بطريقة تهرّب محارف HTML الحساسة.

## عناقيد البحث ذات الأولوية

تُستخدم العبارات التالية لفهم نية الباحث وبناء صفحات مفيدة، ولا تُكرر آليًا داخل النص:

| النية | العبارات الأساسية | صفحة الهبوط |
|---|---|---|
| مورد محلي | توفير عمالة مكة، توريد عمالة مكة، عمالة للشركات في مكة | `/locations/makkah` و`/services/manpower-supply-makkah` |
| تشغيل وصيانة | شركة تشغيل وصيانة مكة، فرق تشغيل وصيانة مكة | `/services/operations-maintenance` |
| فنيون | فنيين صيانة مكة، فرق فنية متعددة المهن مكة | `/services/technical-teams` |
| موسمي عام | عمالة موسمية السعودية، حلول تشغيل المواسم | `/seasons` |
| رمضان | توفير عمالة موسم رمضان، عمالة رمضان مكة، فرق تشغيل رمضان | `/ramadan` و`/sectors/seasonal-ramadan` |
| الحج | توفير عمالة موسم الحج مكة، فرق تشغيل الحج | `/hajj` و`/sectors/seasonal-hajj` |
| قطاعي | عمالة فنادق مكة، عمالة مستودعات مكة، عمالة منشآت تجارية مكة | صفحة القطاع المطابقة |

لا تُستهدف عبارة «شركة مقاولات» باعتبارها نشاط الشركة. يجوز أن تشرح صفحة توفير العمالة للمشروعات الإنشائية الفرق بوضوح حتى لا يلتبس النشاط على العميل أو محرك البحث.

## قواعد إضافة نشاط جديد

لا تُنشر صفحة النشاط إلا بعد تحقق جميع البنود التالية:

1. النشاط خدمة فعلية يمكن للشركة مراجعة طلبها، وليس مجرد كلمة ذات حجم بحث.
2. للصفحة نية بحث مختلفة ومحتوى فريد: وصف المهمة، نطاق الخدمة، خطوات البدء، بيانات الطلب، وأسئلة خاصة بها.
3. العنوان والوصف والرابط واضحون ولا يكررون صفحة موجودة بصياغة طفيفة.
4. لا تُذكر أعداد متاحة أو اعتمادات أو زمن استجابة أو نطاق جغرافي غير موثق.
5. للصفحة رابط واحد على الأقل من صفحة الخدمات، وروابط إلى خدمات أو أدلة مرتبطة.
6. `updatedAt` يعكس تعديلًا مهمًا للمحتوى، ولا يُغيّر آليًا عند البناء أو كل طلب.
7. بيانات `Service` المنظمة تطابق النص الظاهر للمستخدم ولا تحتوي على بيانات شخصية أو ادعاءات إضافية.
8. يضاف اختبار للمسار والعنوان والـ canonical وخريطة الموقع قبل النشر.

يُمنع إنشاء صفحات مكررة لكل حي أو صيغة كلمة مفتاحية أو مدينة لا تخدمها الشركة فعليًا. هذا النمط يضعف تجربة المستخدم وقد يندرج ضمن صفحات البوابة أو المحتوى الموسع قليل القيمة.

## الفهرسة والروابط

- كل صفحة عامة مهمة متاحة عبر رابط `<a>` فعلي من التنقل أو السياق، وليست معتمدة على البحث الداخلي أو JavaScript فقط.
- صفحات الخدمات والأدلة تستخدم مسار تنقل مرئيًا و`BreadcrumbList` متطابقًا.
- صفحات البوابات والبحث الداخلي وواجهات API خارج خريطة الموقع، ومحجوبة عن الفهرسة برأس `X-Robots-Tag`؛ صفحة نتائج البحث غير محظورة في `robots.txt` حتى يستطيع الزاحف رؤية توجيه `noindex`. البوابات محمية بالمصادقة، لأن `robots.txt` ليس وسيلة أمن.
- عناوين canonical تستخدم عنوان الموقع العام الحالي. عند ربط نطاق مملوك للشركة، يجب تغيير `SITE.url` ثم إعادة البناء وفحص جميع canonical وOpen Graph وخريطة الموقع والبيانات المنظمة.

## البيانات المنظمة

- الصفحة الرئيسية: `Organization` و`ProfessionalService` و`WebSite`، و`FAQPage` عندما يكون قسم الأسئلة ظاهرًا.
- صفحات الخدمة والقطاع والموقع: `Service` و`BreadcrumbList` و`FAQPage` عندما تظهر الأسئلة للمستخدم.
- الدليل ودراسة الحالة: `Article` و`BreadcrumbList` مع تاريخ نشر وتعديل ثابتين.
- صفحات التجميع: `CollectionPage` بقائمة العناصر المنشورة نفسها.
- لا تضاف نجوم تقييم، أسعار، هاتف، ساعات عمل، إحداثيات أو ملفات اجتماعية قبل توفر بيانات صحيحة وقابلة للتحقق.

## ضوابط الأمان المرتبطة بالبحث

- سياسة CSP تمنع المصادر الخارجية والإطارات والكائنات، وتسمح بالأنماط والبرامج المضمنة حاليًا لتوافق Vinext والترطيب. الانتقال إلى nonce يحتاج تحويل الصفحات إلى توليد ديناميكي واختبار أثره في التخزين المؤقت والأداء قبل اعتماده.
- رؤوس HSTS و`nosniff` ومنع الإطارات وسياسة الإحالة والصلاحيات وCOOP وCORP تُطبق مركزيًا.
- لا تدخل أي قيمة يرسلها زائر في JSON-LD أو metadata.
- البحث العام لا يفهرس صفحة النتائج، ولا تُعرض بيانات البوابات ضمن فهرس البحث العام.
- أي محتوى ينشئه المستخدم يحتاج مراجعة ومكافحة إساءة قبل عرضه علنًا؛ الموقع الحالي لا ينشر محتوى المستخدم.
- المسودات تُزال من الحمولة العامة قبل تمرير المحتوى إلى مكونات المتصفح، كما تُستبعد من البحث الداخلي وخريطة الموقع والبيانات المنظمة.

### سجل مراجعة سلسلة التوريد

- في 2026-08-14 رُفعت نسخ Next وReact وVinext وVite وCloudflare، ونجح `npm audit --omit=dev` دون ثغرات معروفة في تبعيات الإنتاج.
- يبقى في الفحص الشامل تحذيران في أدوات البناء فقط: نسخة `esbuild` قديمة تأتي من `drizzle-kit` المستقر، ومحلل `image-size` داخل Vinext بلا إصدار مصحح متاح وقت المراجعة. لا تدخل هذه الحزم في مسار طلبات الإنتاج؛ خادم التطوير غير منشور للعامة، وأصول الصور التي يعالجها البناء محفوظة في المستودع ولا يمرر إليها رفع الزوار. يجب إعادة الفحص عند صدور تحديث upstream، وعدم تشغيل أدوات التطوير على شبكة عامة.

## القياس بعد ربط الخدمات الخارجية

عند توفر ملكية النطاق وحسابات الشركة:

1. إضافة الموقع إلى Google Search Console وBing Webmaster Tools والتحقق من الملكية.
2. إرسال `/sitemap.xml` ومراقبة صفحات «تم الزحف ولم تتم الفهرسة» وأخطاء البيانات المنظمة.
3. إنشاء أو توثيق ملف Google Business Profile بعنوان حي الرصيفة، وإضافة الهاتف وساعات العمل والفئات والخدمات الحقيقية نفسها في الموقع والملف.
4. قياس الاستعلامات والصفحات وطلبات عرض السعر دون تسجيل محتوى المحادثات أو البيانات الشخصية في أدوات التحليلات.
5. مراجعة Core Web Vitals على بيانات المستخدمين الحقيقية، ثم معالجة الصفحات ذات الأثر الأعلى.

## دورة المراجعة

- شهريًا: أخطاء الزحف، الصفحات المفهرسة، الاستعلامات، الروابط المعطلة، وطلبات العرض حسب صفحة الدخول.
- ربع سنويًا: دقة الخدمات والمحتوى والروابط الداخلية والبيانات المنظمة وتواريخ التعديل.
- فورًا: أي تغيير في اسم الشركة أو النطاق أو العنوان أو الهاتف أو ساعات العمل أو نطاق الخدمة.
