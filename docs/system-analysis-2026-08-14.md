# تحليل منصة دالي وخطة الظهور العضوي المنفذة

تاريخ المراجعة: 2026-08-14

## الخلاصة التنفيذية

كانت المنصة قوية تشغيليًا: مصادقة خادمية، صلاحيات، D1، ملفات محمية، تدقيق، إشعارات، محادثة مباشرة، طلبات عروض أسعار، وبوابات عميل وعامل. كانت الفجوة الأساسية أن الموقع العام ثابت في الشيفرة، لذلك لا يستطيع مستخدم النظام تطوير المحتوى أو إضافة نشاط جديد دون تعديل برمجي.

حُولت هذه الفجوة إلى وحدة إدارة محتوى مرتبطة ببنية المنصة نفسها. يدير المستخدم المخوّل هوية الشركة والصفحة الرئيسية وإعدادات SEO والخدمات والقطاعات ومناطق الخدمة والمشروعات والاعتمادات والمعرفة والوظائف والشركاء والأسئلة الشائعة وحالة ظهور كل قسم. كل نشر يمر بصلاحية خادمية وتنقية وقفل إصدار وتدقيق وإشعار.

## المقارنة الوظيفية

المواقع المنافسة الظاهرة في نتائج مكة تميل إلى صفحات خدمة محلية منفصلة، وأقسام قطاعات، وأرقام ثقة وشعارات عملاء، وصفحات تشغيل وصيانة أو عمالة موسمية. نُفذت العناصر المفيدة بنهج أكثر تحفظًا:

| النمط الشائع | قرار دالي |
|---|---|
| صفحات لكل صيغة كلمة أو حي | صفحة مكة واحدة غنية وقابلة للتوسع فقط عند وجود تغطية ومحتوى فريدين |
| أرقام وشعارات بلا مصدر ظاهر | أقسام مشروعات واعتمادات وشركاء فارغة افتراضيًا ولا تنشر إلا بعد توثيق الإدارة |
| وصف عام متكرر | صفحة مستقلة لكل نية خدمة أو قطاع مع نطاق وبيانات طلب وأسئلة خاصة |
| الاعتماد على نموذج اتصال واحد | عرض سعر، محادثة مباشرة، توظيف، شراكة، وشكاوى؛ كلها تصل للنظام برقم متابعة وإشعار |
| كلمات مفتاحية مكررة | عناقيد نية بحث وروابط داخلية وبيانات منظمة ومحتوى قابل للتحديث |

## الأقسام المضافة

- القطاعات: الضيافة والفنادق، المنشآت التجارية والإدارية، المستودعات واللوجستيات، المشروعات الإنشائية بوصفها توفير قوى عاملة لا مقاولات، والتشغيل الموسمي والحج.
- مناطق الخدمة: مكة المكرمة مع إشارة دقيقة إلى مقر حي الرصيفة ومن دون ادعاء زمن وصول أو تغطية غير موثقة.
- المشروعات وسابقة الأعمال، والتراخيص والاعتمادات: لا تفهرس وهي فارغة، وتصبح قابلة للفهرسة بعد نشر بيانات حقيقية.
- الوظائف: لا تفهرس قائمة فارغة، مع نموذج اهتمام عام يحذر من إرسال وثائق هوية.
- الموردون والشركاء: قناة مؤسسية ورفض افتراضي لعرض أسماء أو شعارات غير معتمدة.
- الأسئلة الشائعة، والشكاوى والاقتراحات، ومركز معرفة قابل للتحرير.

## إدارة الموقع

1. يفتح المستخدم المخوّل «إدارة الموقع الإلكتروني» من البوابة.
2. يعدل النصوص أو يضيف عنصرًا كمسودة، ويحدد الرابط الإنجليزي والعنوان والوصف والكلمات والوسوم وأقسام الصفحة والأسئلة.
3. يراجع العنصر في حالته ومساره، ثم يحوله إلى «منشور» ويحفظ النسخة.
4. يتحقق الخادم من الصلاحية والمصدر والنوع والحجم والنسخة، ثم ينقي كل حقل ويحفظ النسخة الجديدة.
5. يسجل النظام النشاط ويرسل إشعار نشر، وتظهر النسخة العامة في البحث وخريطة الموقع والروابط بحسب حالة الظهور.

لا يقبل المحرر HTML خامًا أو صورًا خارجية. مسارات الصور محصورة في مكتبة الصور المعتمدة داخل المشروع للحفاظ على الأمان واشتراط خلو الصور العامة من الكائنات الحية.

## ضوابط SEO المنفذة

- عنوان ووصف وكلمات موضوعية قابلة للإدارة، وcanonical وOpen Graph وTwitter metadata.
- `Organization` و`ProfessionalService` و`WebSite` و`SearchAction`، مع `Service` و`Article` و`CollectionPage` و`BreadcrumbList` و`FAQPage` بحسب الصفحة والمحتوى الظاهر.
- خريطة موقع ديناميكية تستبعد المسودات والأقسام المخفية والقوائم الفارغة غير المفيدة.
- بحث عام يشمل الأقسام الجديدة ويستبعد المخفي والمسودات، وبحث إداري يشمل محتوى الموقع ضمن صلاحية المستخدم.
- صفحات نتائج البحث والواجهات والبوابات والشكاوى والقوائم الفارغة تحمل `noindex` وفق الغرض.
- ربط داخلي بين الصفحة الرئيسية والخدمات والقطاعات ومكة والمعرفة ونماذج التحويل.
- محتوى محلي دقيق لحي الرصيفة ومكة، مع منع صفحات الأحياء الرقيقة والكلمات المحشوة والادعاءات غير القابلة للتحقق.

## ضوابط الأمن والخصوصية

- تحقق الهوية والصلاحية في الخادم؛ إخفاء واجهة الوحدة ليس ضابط الوصول الوحيد.
- حماية من الطلبات متقاطعة المصدر، قبول JSON فقط، وحد معلن ومتحقق لحجم محتوى الموقع.
- تنقية نصوص وslugs وروابط HTTPS ومسارات الصور، وعدم إدخال محتوى الزوار في metadata أو JSON-LD.
- قفل تفاؤلي برقم الإصدار ومقارنة وقت تحديث D1 لمنع الكتابة فوق تعديل متزامن.
- المسودات وبريد محرر آخر تحديث لا تصل إلى حمولة الموقع العامة.
- سجل تدقيق وإشعار عند نجاح النشر، وفصل الموقع العام عن البوابة الإدارية.
- CSP وHSTS ومنع الإطارات و`nosniff` وسياسات الصلاحيات والإحالة والمصدر مطبقة مركزيًا.
- نماذج عامة بموافقة خصوصية وحقل طُعم ومفتاح عدم تكرار وتقييد موزع، مع تحذير من إرسال وثائق أو بيانات حساسة.

## ما يلزم خارج الشيفرة

لا تستطيع الشيفرة وحدها ضمان المركز الأول. بعد اعتماد هاتف الشركة وساعات الدوام والسجل والنطاق المملوك، تُستكمل الخطوات التالية:

1. ربط نطاق يعكس اسم «دالي للتشغيل والصيانة» بدل النطاق التجريبي الذي يحتوي على contracting.
2. توثيق Google Business Profile بنفس الاسم والعنوان والهاتف والساعات والفئات والخدمات، وإدارة المراجعات بصدق.
3. التحقق في Google Search Console وBing Webmaster Tools وإرسال خريطة الموقع.
4. نشر مشروعات واعتمادات وشركاء موثقين فقط، وكسب إشارات وروابط محلية حقيقية من جهات ذات صلة.
5. قياس الاستعلامات والتحويلات وCore Web Vitals شهريًا، ثم تحديث الصفحات وفق بيانات فعلية لا وفق تخمين حجم البحث.

## مؤشرات المتابعة

- الصفحات الصالحة والمفهرسة، والاستعلامات غير المرتبطة بالعلامة التجارية، ومتوسط موضع كل عنقود.
- ظهور ملف النشاط في نتائج الخرائط، والمكالمات وطلبات الاتجاه والمراجعات الحديثة.
- طلبات عروض الأسعار والمحادثات المؤهلة حسب صفحة الدخول، مع تجنب تخزين نصوص حساسة في التحليلات.
- LCP وINP وCLS على بيانات مستخدمين حقيقية، وأخطاء البيانات المنظمة والروابط المعطلة.
- نسبة المحتوى المحدث خلال 90 يومًا، وصفحات ذات ظهور بلا نقر التي تحتاج تحسين عنوان أو إجابة.
